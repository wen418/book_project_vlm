# 电梯按键、楼层与进梯量化测试

更新：2026-10-20。上位机目录：`/media/data/vlm/elevator_button_floor_demo`。当前量化默认“回原点不转向”，已取消门中心平移方案。

**识别对错可从 report.html 进入“看图核验识别对错”，边看图边选真值并导出 labels.csv。门、按键、楼层 VLM 最大请求频率统一为 1 Hz。按键点亮和门全开的延迟都可选帧核验，无需手填时间戳。未完成所选流程的轮次判失败，不保存到 result。** 连续图像需要用本版程序重新采集；旧版已有的自动耗时仍可直接查看，旧截图不能补回缺失的连续过程。部署与验证状态见 `验证记录.md` 最新条目。

本次“量化”指实验耗时和成功率统计。新程序是本目录的 `elevator_quantification.py`，沿用原来的两个感知节点与下位机正式单文件入口；通过 SSH 将下位机事件送回上位机。原流程默认不变。

## 1. 最常用的启动方式

在**上位机**终端运行；真实进梯前需按现场流程启动主控、电机、定位和导航，核对地图、点位与急停。程序不会自动初始化机器人。

```bash
cd /media/data/vlm/Demo_kuavo_vlm_api

# 原按钮/楼层完整演示：不加参数等价于 --program demo
./start_elevator_demo.sh

# 新量化程序：先检查依赖、硬件、相机和真实运动反馈，不执行动作
./start_elevator_demo.sh --program quantify --check

# 无动作部署检查：启动两个空闲感知并验证记录器能解码相机，然后退出
./start_elevator_demo.sh --program quantify --check-startup

# 原路线基线对照（允许底盘转向），完成进梯后结束
./start_elevator_demo.sh --program quantify --entry-only \
  --entry-plan baseline --door-condition unassisted --trial-note "基线第1轮"

# 量化完整流程，默认回原点不转向，无需提供新坐标
# 按钮→保持朝门回原点→进梯→看屏幕→目标层→看门→出梯
# 会同时收集正常、转头视角；默认目标层沿用下位机现场配置
./start_elevator_demo.sh --program quantify --door-condition unassisted

# 只测保持朝门回原点及进梯；显式指定也可以
./start_elevator_demo.sh --program quantify --entry-plan origin_no_turn \
  --entry-only --door-condition unassisted

# 如需单次改目标层，追加 --target-floor 19；地图是否适用仍需现场核对
```

也可以从新程序直接进入相同的一键调度：

```bash
# 先在同一终端按原脚本加载 ROS 环境；或直接使用上面的启动脚本
python3 /media/data/vlm/elevator_button_floor_demo/elevator_quantification.py --help
```

完成所选流程且正常退出的量化轮次，其子进程日志、图像和报告统一进入本目录的 `result/`。原 `--program demo` 的日志仍在原一键目录的 `logs/`。

## 2. 回原点不转向，或减少回退

考虑门中心平移后看不见完整门，已移除 `center_shift`，旧参数会明确报错。保留以下三种方案，均先将头部恢复看门，再前往厅外观察点，在该点用新图像确认门完整打开，才去 `inside`。

| 方案 | 参数 | 坐标和回退朝向 |
| --- | --- | --- |
| 原路线对照 | `--entry-plan baseline` | 使用现场 origin，允许原导航转向 |
| 回原点不转向（量化默认） | `--entry-plan origin_no_turn` | 使用现场 origin，无需新坐标；仅回退段设置 allow_rotation=false |
| 减少回退并保持朝门 | `--entry-plan reduced_backtrack` | 用户确认点 x=-0.901m、y=0.004m、theta=6°；可不传坐标；该段同样禁止转向 |

“不转向”指底盘在**按钮点→原点/较近观察点**这段保持开始时实测朝向，不只是终点再朝门。程序已经核对现场 SDK：`NodeNavigationToTarget` 将 `allow_rotation` 传入 `MoveToTargetOptions`，其消息定义明确为“是否允许旋转”。其他导航段仍允许旋转，原 `inside` 朝向、进梯后的转身和楼层观察流程保留。

保持朝门回退可能省掉原来先转向行进、到点再转回的时间，但倒退路径和速度也会影响总耗时，须实测比较。这个方案不保证沿一条直线后退：沿用原 x/y 目标，路径仍由现有底盘导航求解，没有新增门中心平移目标。

用户已明确确认截图标注是 **(-901 mm, 4 mm, 6°)**，已换算成减少回退方案的默认点 **(-0.901 m, 0.004 m, 6°)**。第三个数是朝向，不按毫米换算。它是地图中的绝对点，不是相对位移；不覆盖现场永久 origin/button/inside/exit。切换到该方案无需再输入坐标，但仍需现场检查此点是否能看全门、回退路线是否可行。

回退前用真实定位确认底盘已经朝门：与现场 `origin.theta` 偏差不超过10°；不满足时不发回退指令。此方向容差允许用户确认的6°与原点配置0°的小差异，不表示已经验收视野。回退目标的 theta 使用出发时实测角度，避免要求到点再做小角度对齐。途中保存实际朝向，完成回退后检查全程采样的最大角度变化不超过5°且反馈有效，否则不继续等门/进梯。采样不能证明每个瞬间绝对零旋转，禁转及倒退效果仍须现场验证。

使用已经确认的点：

```bash
./start_elevator_demo.sh --program quantify --entry-plan reduced_backtrack \
  --entry-only --door-condition unassisted
```

如以后需要覆盖成另一个经过现场核对的新点，再输入坐标：

```bash
read -r -p "输入已核对的厅外观察点 x y theta（米 米 度）：" WAIT_X WAIT_Y WAIT_THETA
./start_elevator_demo.sh --program quantify --entry-only \
  --entry-plan reduced_backtrack --entry-pose "$WAIT_X" "$WAIT_Y" "$WAIT_THETA" \
  --door-condition unassisted --trial-note "减少回退第1轮"
```

`origin_no_turn` 使用原点；`reduced_backtrack` 使用上述用户确认点；都不必手动传坐标。只有需要另换点时才加 `--entry-pose`；无效坐标或朝向会拒绝启动。自定义点朝向须与原点朝门方向相差不超过10°。新点必须仍能完整观察电梯门，缩短距离不代替视野验收。

建议每种方案先分别做多轮同条件测试，包含**无人挡门的自然开门周期**。`--door-condition unassisted` 只记录计划条件，不能证明现场没有人挡门；运行后必须在人工复核中填写实际条件。中途有人帮忙挡门的轮次应改标为 `held`，不要混进无人挡门成功率。

每轮结束后需由现场人员恢复合适的起始点；`--entry-only` 结束时机器人留在梯内，不自动返回原点。

## 3. 正常/转头视角及正确、错误实例

完整量化流程根据**头部实测到位事件**区分 `normal`（看门/按钮）与 `turned`（看屏幕）；运动中的图像标为 `head_moving`。没有头部到位事件时标为 `unverified`。每两秒另存一帧时间线图，头部到位后另存新帧。

第一次等门阶段与按键观察阶段分别保存约每0.1秒一帧的连续图像，用于事后确定门全开、下行按钮点亮的画面时间，包含观察开始前约1秒的已有缓存及确认后至多约1秒画面（以实际收到的图像为准）。此序列独立于每两秒的普通时间线图，实际间隔和丢帧以源图像时间戳为准。

只采当前视角感知、不导航也不转头，可以这样运行。此时视角标签由现场人员提供；保持当前已经调整好的头部姿态：

```bash
./start_elevator_demo.sh --program quantify --observe-only door --view normal
./start_elevator_demo.sh --program quantify --observe-only floor --view turned --target-floor 20
./start_elevator_demo.sh --program quantify --observe-only button --view normal
```

单独感知仍使用原证据门控：按钮等点亮、楼层等目标层、门等完整开放；未满足时会继续记录结果，直至确认、超时或 Ctrl+C。按新保存规则，超时、报错、Ctrl+C 或未确认就退出的轮次不保存；需要保留未亮/错误识别的过程，必须让该次所选流程最终正常完成，过程中的负例才随整轮一起保存。它不会为了凑错误样例而修改识别结果。

每条识别结果按 `image_stamp` 匹配**同一源帧**，保存原始视野的 JPEG 复核图；没有精确匹配帧则标 `missing`，不用邻近帧顶替。复核图经过 JPEG 编码，不宣称与模型上传字节完全相同。模型可能使用 ROI、缩放、时序过滤，实际门节点参数和下位机有效配置另存于 `run.json`。

打开每轮的 `report.html`，点击 **“看图核验识别对错”**，也可直接用浏览器打开同目录 `labels_review.html`。不用在CSV与图片之间来回查找：

1. 页面左侧显示该条识别对应的完整源图，点击图片可放大；右侧选择画面真实状态。门选完全关闭/完全打开/无法判断，按钮选点亮/未亮/无法判断，楼层填写实际显示的整数。程序自动给出正确、错误或模型未作答，不用自己改预测。
2. 支持门/按键/楼层筛选、只看未标注或错误实例、标完自动下一张，以及方向键翻图、1/2选择状态、U表示无法判断。每条只填一次；不强制全部标完，未标注会单独统计，不充作正确。半开、开关过程和遮挡看不清都不能标为门完全打开。
3. 看不到对应源图时不允许填写确定的真值，可跳过或标无法判断；没有匹配到的原帧不拿邻帧替代。页面会说明模型可能用裁剪或缩放，所见复核图是完整源视野。
4. 点“导出 labels.csv”，把下载文件放回本轮文件夹覆盖原CSV；关闭页面前先导出。分次标注时先导入之前导出的CSV，页面校验记录编号、类型、图片和预测一致，只接收人工真值与备注，避免串轮。原CSV中的手填真值会自动加载，格式错误可在页面重新选择修正。
5. 将 labels.csv 回传上位机同一轮目录；若还做了门/按键时间核验，则同时回传 trial_review.json。**识别对错需要逐条核对实际识别结果帧；时间核验只标变化前后两帧，不用标所有连续图。**
6. 在上位机执行下面的 review 更新报告；aggregate 更新多轮时间汇总。

页面导出的CSV仍使用原 `ground_truth` 与 `note` 格式：门 `door_closed` 完全关闭为true、完全打开为false；按键亮为true、未亮为false；楼层为整数；无法判断为null，留空为待标注。也可继续手动编辑CSV。

旧轮次没有看图入口时，用新版程序离线补网页，不改变原始数据或人工标注：

```bash
cd /media/data/vlm/elevator_button_floor_demo
python3 elevator_quantification.py prepare-review result/本轮目录名
```

补好后重新下载整轮文件夹，或者把新生成的 report.html、labels_review.html、door_review.html、button_review.html 下载覆盖到本机同一轮目录，保留原 images 子目录。网页可在本机浏览器直接打开。普通Windows Python也能执行本地程序的 prepare-review，不需要ROS、API密钥或连接机器人。

```bash
cd /media/data/vlm/elevator_button_floor_demo
python3 elevator_quantification.py review result/本轮目录名
python3 elevator_quantification.py aggregate result
```

复核结果分为 `correct`、`incorrect`、`abstained`（有真值但模型未知/错误状态）、`ground_truth_unknown`、`unreviewed`。报告会显示正确/错误实例，并分别给出回答样本准确率、包含弃答的正确率和覆盖率；未标注/真值不明不混入准确率。没采到错误实例就如实保留，不生成假例。

对比汇总生成 `result/comparison.csv` 与 `comparison.json`，按方案、回退禁转策略、新点、实际门条件、地图/点位、头部和导航/证据配置分组。每项时间单独给出有效样本数、均值、P50、P95，成功率只使用人工已验收的进梯轮次；无动作部署检查不纳入实验。

## 4. 请求频率与时间定义

门、按键、楼层统一按 **1 Hz 的最大请求频率**调度，每次取当前阶段的新鲜最新帧，不对相机每帧调用模型，不需要追加启动参数。每个节点同步调用云端 VLM，若单次推理超过1秒，实际输出频率会低于1 Hz；不会并发堆积过期请求。每条结果的 latency_ms 如实记录，心跳每秒发布不代表每秒有一条新识别结果。连续核验图像约10 Hz，与 VLM 请求频率分开。启动检查会拒绝复用频率不符的旧节点，需先退出旧感知实例再重新运行。

**这些耗时都由程序自动记录，不需要拿秒表计时，也不用人工填写长时间戳。** 每轮结束后直接打开 `report.html`，顶部“自动计时结果”显示各段秒数，或查看 `timings.csv`。人工主要核对图像识别是否正确、是否有人挡门、实际进梯是否成功。

下位机内部的耗时统一使用该机的单调时钟，不用上下位机系统时间相减。相机和动作另记 ROS 时间戳，用于对图和人工视频对齐。

| 结果字段 | 含义 |
| --- | --- |
| `button_wait_to_first_positive_s` | 开始观察按键 → 首次通过新鲜度、请求ID和置信度校验的点亮结果 |
| `button_wait_to_recognition_s` | 开始观察按键 → 连续两帧、源图像跨度至少1秒的点亮确认 |
| `button_confirmation_s` | 首次有效点亮结果 → 连续确认通过，单独显示确认等待 |
| `button_inference_s` | 最终被接受点亮结果的调用链 latency_ms / 1000 |
| `actual_button_lit_to_first_positive_s` | 人工选定首张点亮帧 → 首次有效识别；review 后生成 |
| `actual_button_lit_to_recognition_s` | 人工选定首张点亮帧 → 连续确认通过；review 后生成 |
| `door_wait_to_recognition_s` | 本次开始等门 → 首次被证据门控接受的完整开门结果；包含等电梯、采样间隔、推理和接收 |
| `door_inference_s` | 被接受开门结果自带的 `latency_ms / 1000`，是现有感知调用链耗时，含网络/解析及可能的重试，不是 GPU 纯前向时间 |
| `recognition_to_command_s` | 开门确认 → 开始调用进梯导航 API |
| `command_call_s` | 进梯导航 API 调用开始 → 发送节点返回成功；不是底层电机控制器的精确收包时间 |
| `command_to_motion_s` | API 调用开始 → 实际定位反馈首次达到运动阈值的接收时刻 |
| `motion_to_entry_s` | 实测起步 → 导航到达 `inside` 反馈成功 |
| `recognition_to_entry_s` | 开门确认 → 导航到点成功 |
| `wait_to_entry_s` | 开始等门 → 导航到点成功 |
| `entry_settle_s` | 到点成功后的原有稳定等待，单独列出，不混进进梯运动时间 |
| `return_navigation_s` | 开始返回厅外观察点 → 导航到点成功，可比较是否省掉转向时间 |
| `return_settle_s` | 返回观察点后的稳定等待 |
| `button_to_door_wait_s` | 按钮点亮确认 → 开始等门，含恢复头部看门、回退及稳定等待 |

另记 `return_max_heading_change_deg`（相对回退出发时朝向的最大角度变化）与 `return_heading_status`（是否通过实测朝向检查）。原五段进梯指标从等门才开始，不能用它们单独判断回退是否节省时间；对照时应同时比较新增的回退指标。

额外的**门实际全开→程序确认**、**下行按钮点亮→首次识别/连续确认**延迟，需要人工核对画面变化。“开始等门”不等于门物理打开，程序自身的判断也不能当成独立真值。现在不要求用户自己知道时间，按下面操作即可：

1. 运行结束，打开本轮 `report.html`，点击“打开开门时间核验”（也可直接打开 `door_review.html`）。
2. **不用逐帧都标**。用滑块、播放或上一帧/下一帧，找到门最后一张尚未全开的画面，点“标记未全开”。
3. 向后逐帧看，在**第一张完全敞开**的画面点“标记全开”。程序直接使用选中图像的原始时间；不用看电脑时钟、手机录像时间，也不用抄数字。
4. 页面立即显示两帧间隔、首张全开帧到程序确认的秒数及延迟范围。填写实际挡门情况、进梯成功和备注后点“导出 trial_review.json”。
5. 在页面顶部把“核验对象”切到“下行按钮点亮”，同样标记最后未亮与第一张点亮图像；页面会显示到首次有效识别、到连续确认的两项延迟。可在门和按键之间切换，标记会一起导出。
6. 把下载文件放回**这一轮**目录，文件名保持 `trial_review.json` 并覆盖原文件，再执行上面的 `review` 命令更新正式报告。

按键核验也可直接从报告打开 `button_review.html`，两个入口是同一个可切换的核验页面。继续之前已导出的标注时，先用页面的“导入”选择该 trial_review.json，避免用另一个旧页面覆盖已有标注。按键测的是可见点亮，不等同于机械按压；开头已亮、灯被遮挡或没有拍到变化时请清除，时间保持空值。执行 review 后自动更新 timings.csv、summary.json 和报告，aggregate 会统计这些延迟；两帧范围单独存入 summary.json。

只标第一张全开帧也可以，程序能计算“首张全开帧到确认”的差值；但没有此前未全开帧，无法给出物理全开发生的时间范围。推荐标两帧，且都要尽量靠近变化边界；开头已全开时不应把第一张可见帧当作首次全开。

示例（仅解释口径，不是真实实验数据）：上一张未全开在10.0秒，第一张全开在10.1秒，程序在10.7秒确认，则页面显示首张全开帧到确认 **0.6秒**，物理全开到确认的时间范围为 **[0.6,0.7)秒**。门真正全开发生在两帧之间，不能声称精确到某一个瞬间；实际采样间隔可能大于0.1秒，页面据实显示。

若程序确认比人工选定的全开帧还早，保留负值并提示检查是否误放行，不强行改成0。若开头已经全开、门看不清、没有拍到由未全开到全开的过程，点“无法确定/清除”，保持时间空值；其他自动计时照常可用。以前版本每两秒的稀疏截图无法补回连续过程，要用新版本重新采集，不能用旧结果伪造高精度时间。

这项额外延迟用相机时间戳与下位机确认时刻相减，现场还需确认相机所在机器与下位机的时钟同步；连接同一个 ROS Master 本身不保证时钟同步。页面的两帧间隔只描述视觉采样误差，不包括跨机时钟偏差。若同步没有确认，保留为基于 ROS 时间的估计，不能宣称达到0.1秒的总体测量精度；负值也需要排查时钟偏差。其他自动耗时使用下位机同一单调时钟，不受此项影响。

起步默认订阅 `/jarvis/pose`（`nav_msgs/Odometry`，现场验证为 map 坐标、base_link 底盘位姿），仍支持 `geometry_msgs/PoseStamped`。2026-10-20 现场查明旧默认 `/tracked_pose` 没有发布者，已修正；启动时会单独报告“没有发布者”，避免与过期或移动混淆。可用 `--motion-topic` 指定其他实际话题，但保持朝门时需确保该位姿与导航点使用同一地图坐标系，不能直接拿局部 odom 朝向代替地图朝向。只接受新鲜、不同时间戳的反馈；发令前须有短时静止基线，发令后相对基线平移达到 **1.5 cm** 或旋转达到 **0.03 rad**，连续三帧确认，回填第一帧越阈值时刻。该定义存在阈值/采样延迟，不宣称是第一瞬间电机转动。源时间、接收时间和轨迹样本都保留。

没有反馈时会在动作前拒绝；开始后反馈丢失、跳变、坐标系改变、没观察到起步时，该项保留 `null` 并注明原因，不以导航指令或零秒替代。**进梯完成以原导航到点（包含原 inside 朝向）反馈为准**，不是自动判断整机几何跨过门槛，仍需人工结合录像确认成功。

保存以所选模式的最后一步为准：完整流程必须完成出梯；`--entry-only` 必须完成进梯；`--observe-only button/floor/door` 必须通过对应的确认门控。均要求下位机明确发送 `workflow_completed`、最终导航/确认反馈存在、事件连续、记录器无错误且退出码为0。仅到达阶段开头、开始发令或中途 Ctrl+C 都不算完成。

运行中先写入 result 同级的 `.result_pending/轮次名`；正常完成后整轮原子移入 result。提前终止、超时、报错或生成报告失败会删除临时轮次，包括图片和子进程日志，不生成失败报告。`--check-startup` 没有业务完成标记，也不留下结果。突然断电或 kill -9 无法当场清理，下一次启动量化时会检查进程已结束的临时轮次并删除；这些临时内容不属于 result。已确认的正式失败轮 `20261020_143500_0793a6cb` 较早已删除；2026-10-20用户进一步要求清理历史诊断及旧版正式轮，本次删除4个诊断、旧轮20261020_144748_2907e9a8及过期comparison.csv/json，清理后result为空。

按本次要求仅保留完成轮次，因此 result 的样本不能用于计算全部尝试的成功率；如需总体成功率，现场需另行统计总尝试数及失败数。保留轮次中的错误识别实例仍可人工标注。Ctrl+C 仍先中止远程程序并清理本次节点；底盘仍沿用现场急停处理。
