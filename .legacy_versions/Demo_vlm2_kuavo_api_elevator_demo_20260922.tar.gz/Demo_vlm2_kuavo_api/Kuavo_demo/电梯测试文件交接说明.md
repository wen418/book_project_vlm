# Kuavo 电梯门感知与进出 Demo

本目录把已有的两个独立能力串成一个单轮演示：

```text
门外原点等待完整开门
  -> 进入轿厢并转身面向门
  -> 等待确认门关闭
  -> 等待门再次完整打开
  -> 退出到门外原点
```

门关闭、半开、正在开关、识别未知、结果过期或网络异常时，程序都不会下发下一段导航。进入轿厢后必须先看到门关闭，再接受下一次开门，避免第一次开门状态残留导致机器人立即退出。

## 文件

| 文件 | 用途 |
| --- | --- |
| `elevator_text_main.py` | 预览、mock 和实机单轮入口 |
| `params/elevator_demo.yaml` | 21 楼点位、导航与感知门控参数 |
| `tests/test_elevator_text_main.py` | 不连接机器人和 API 的离线测试 |
| `部署与合并说明.md` | 从两个独立功能到 ROS 联动 Demo 的完整部署、验证、启动与回退流程 |

感知节点仍位于 `Demo_vlm2_kuavo_api` 工程，发布：

- 状态：`/elevator/perception/state`（`std_msgs/String` JSON）
- 模式：`/elevator/perception/mode`（`door_monitor` / `idle`）

## 录制前离线检查

在包含本目录的 `book` 路径执行：

```bash
python3 -m unittest discover -s tests -p 'test_elevator_text_main.py' -v
python3 elevator_text_main.py
python3 elevator_text_main.py --mock
```

预览输出中的起点、轿厢内点、返回点必须与现场地图一致。程序假设机器人已经位于门外原点并朝向电梯门；它不会先导航到该点。

## 启动感知

在 AAEON 上加载 API 环境并启动已有节点：

```bash
cd /media/data/vlm/Demo_vlm2_kuavo_api
source deploy/api_env.sh
set -a
source /media/data/vlm/secrets/elevator_vlm_api.env
set +a
deploy/run_ros_api.sh
```

先用 `rostopic echo /elevator/perception/state` 做 shadow test。快速模式现在采用通行语义：

- 完全关门：`door_closed=true`
- 完全开门、入口完整敞开：`door_closed=false`
- 半开、正在运动、看不清：`door_closed=null`

至少现场验证完整开门、完整关门、半开、运动中、反光、遮挡和断网；未通过时不要启动实机动作。

## 实机录制

机器人终端逐行准备环境：

```bash
sudo su
cd /home/lab/kuavo-ros-control
source devel/setup.bash
cd /home/lab/kuavo-ros-control/src/kuavo_humanoid_sdk/kuavo_humanoid_sdk/kuavo_strategy_pytree/book
```

确认急停有效、专人看护、门区无人且点位与朝向均已低速验证后，只运行一次：

```bash
python3 elevator_text_main.py --run --preflight-confirmed --perception-confirmed --estop-ready
```

建议录屏同时包含机器人、电梯门和两个终端：感知终端显示门状态，控制终端显示 `[1/5]` 至 `[5/5]`。

## 重要限制

- VLM 是秒级语义门控，不是安全传感器；必须保留电梯防夹、机器人避障和物理急停。
- 程序异常后只保证不再下发后续目标，不保证撤销底盘已经收到的导航任务；异常立即拍物理急停。
- 当前演示不按楼层、不换地图、不控制电梯，只验证“关门等待—开门通行—轿厢内转身—再次开门—退出”。
- `confirmations` 和 `min_confirmation_span` 是额外规划门控。不要为了缩短录制时间而在未评测的情况下改为单帧放行。
