## 楼层规则

模型问题、模型、图像输入和原置信度门槛不变。过滤器只接收模型读数、真实图像采集时间戳和原置信度；不给模型目标层，不读取人工标签，不按期望路线补数字。13不会自动改写成18。

1. 新的楼层观察请求清空历史。先用两张不同时间戳、相隔至少0.5秒、读数一致的图建立基准。低置信度或未知不能建立基准。
2. 已有基准后，普通合理读数可单次输出。设最后一次接受的楼层为F、采集时间为T，新图采集时间为t，允许变化量为`min(3, 1 + floor((t-T)/4))`。同层始终允许，升/降均支持。
3. 例如F=19：约1.5秒后允许18～20；4.5秒后允许17～21；8.5秒后允许16～22。19→13不会在短时间内被接受。
4. 跳变读数发布未知，保留`floor_raw`及拒绝原因；不更新基准。下一张仍按距上次可信图像的实际时间扩大范围，不按失败次数扩大。
5. 超过12秒没有接受过楼层，基准失效，先未知；连续三张一致读数重新建立基准。不会因等待时间很长而直接允许任意跳变。
6. 控制端对于“到达目标楼层”至少需要两次一致、新鲜且不同时间戳的有效证据；普通中间楼层不重复等待。初始化/重新建立基准的多帧证明可计入到层确认，避免重复等待。未知或其他楼层会打断目标层确认。按钮仍单帧。
7. 至少两次同向的非零楼层变化才确认升/降方向，静止不算方向。方向未知时双向允许；确认下降后，17→18等反向读数进入隔离区，不直接更新基准。同层停留一直允许。
8. 合理读数还需与最近12秒的已接受历史共同一致，避免每次只跳一层却短时间累计跳了很多层。历史总位移不套用单步的3层上限，而按实际经过时间检查。
9. 被拒绝的高置信度读数保留为独立候选轨迹；至少4张、跨至少两个不同楼层、跨度至少4秒、单调且符合时间约束，才能重新建立轨迹。恢复只输出当前原始读数，不补猜中间楼层。候选中断、低置信度或明显不合理跳变会重新积累；恢复本身不能绕过目标层双确认。

默认参数在`floor_filter_config.json`：4秒/层，余量1层，最大跳变3层，基准超时12秒，起始2次、重新建立基准3次、到目标层2次确认。4秒是用户测得的平均速度，不是物理安全上限；运行速度变化可能增加拒答，需实机校准。修改参数需重新运行`build_manifest.py`并验证。

新增方向确认次数2、候选恢复最少4次/4秒、候选相邻间隔不超过5秒。仅重复一个反向数字不能触发方向切换；真实反向后若只到相邻层并停住，可能保持未知，需重新观察请求或人工核验，不能强行当成已到层。

## 局限

这是时序一致性检查，不是楼层真值传感器。持续且自洽的误读、初始基准读错仍可能漏过；没有可靠楼层基准时不会假装已知。没有从地图名或目标层推测起始层/方向；方向来自实际模型读数的趋势，实际反转需另证或重置。

过滤会增加未知及到层等待，不保证不漏层。尤其是显示驻留时间短、实际速度更快、刷新缺段或连续误读时，应继续现场验证；不能凭离线准确率认定可安全自主出梯。

## 运行

上位机使用原系统Python/ROS，退出Conda，先退出旧一键脚本/附加感知节点。新旧方案共享启动锁，不自动杀掉已有节点。

```bash
cd /media/data/vlm/Demo_kuavo_vlm_api/color-button_with_floor-improvement
./start_elevator_demo.sh --check
```

只读检查不启动运动。机器人主控未报告就绪时按原逻辑停止，不自动初始化整机。

先人工对准当前目标，只做静止感知（不导航、不转头）：

```bash
./start_elevator_demo.sh --program quantify --observe-only button
./start_elevator_demo.sh --program quantify --observe-only floor --target-floor 15
```

两条单独测试应分次运行，退出前一个再运行后一个。静止楼层测试只验证当前画面，不能替代乘梯动态测试。

现场确认主控、地图点位、相机、上下位机时钟和急停后，再人工运行完整流程。以下命令**会驱动机器人**：

```bash
./start_elevator_demo.sh --program quantify --entry-plan reduced_backtrack --target-floor 15
```

其他原参数保留；不加检查参数默认仍运行完整演示。原流程不负责物理按键，目标层参数不改变地图/导航点。退出程序不保证底盘制动，沿用现场急停。

## 集成边界

- `button_color_rule.py`的搜索区域与最小尺寸已适配新视角；颜色阈值、按钮schema4/单帧门禁保持原逻辑；固定848×480头部相机。
- `floor_filter.py`为纯Python过滤器及控制端验收；楼层schema6、`floor_backend=floor_track_guard_v2`。数值置信度仍为原模型值，不伪造概率；不与schema5旧版混用。
- `extra_color_node.py`在原楼层API推理完成、发布控制消息前过滤；保存原始楼层、过滤楼层、原因、允许跨度及确认时间戳。心跳不计作新观察，换请求/阶段不复用历史。
- `launcher.py`通过SSH把原下位机快照及按钮/楼层门禁适配传入内存运行，未覆盖下位机原文件；原入口SHA256变化则拒绝继续。导航、回退、转头、门判断及原安全检查代码保持原样。
- `upstream/`是原程序和配置快照。门仍引用`/media/data/vlm/Demo_vlm2_kuavo_api/deploy/run_ros_api.sh`；量化仍引用`/media/data/vlm/elevator_button_floor_demo/elevator_quantification.py`；模型配置、凭据及阶段计时使用原路径，不复制凭据。
- 原量化记录与回退逻辑不改；量化观察记录的是过滤后可给控制端使用的floor，原始模型floor同时保留在payload.floor_raw。原阶段计时的VLM事件仍描述模型调用，不应误当成过滤已放行；实际到层放行看下位机observe_confirmed事件。
- 量化结果默认本目录`result/`，普通日志在`logs/`。`manifest.json`为发布文件哈希检查，不是签名认证。
